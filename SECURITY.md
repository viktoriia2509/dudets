# Security notes

Текущая версия сделана как статический сайт для GitHub Pages. GitHub Pages не выполняет серверный код, поэтому вся логика находится в браузере пользователя.

## Критичные ограничения

1. Админ-логин и пароль проверяются на стороне браузера. Это не полноценная защита.
2. Регистрация пользователей реализована через фронтенд и Firestore/localStorage. Это не замена Firebase Auth или серверной авторизации.
3. Пароль пользователя сохраняется не в открытом виде, а как SHA-256-хэш, но без серверной защиты это всё равно нельзя считать промышленной безопасностью.
4. Если Firestore Rules открыты на запись всем пользователям, любой технически подготовленный пользователь сможет менять данные напрямую.
5. Сайт собирает ФИО, телефон, email и историю заказов. Это персональные данные, поэтому нужны корректные документы, правовые основания, сроки хранения и порядок удаления.

## Что нужно для боевого запуска

1. Подключить Firebase Auth или серверную авторизацию.
2. Разделить роли: покупатель и администратор.
3. Закрыть Firestore Rules так, чтобы обычный пользователь не мог читать и менять чужие данные.
4. Вынести обработку заказов на серверную функцию или иной backend.
5. Разместить реальные документы: политика ПДн, согласие на обработку ПДн, cookie policy, документы по продукции.
6. Проверить требования к дистанционной продаже электронных сигарет и возрастным ограничениям в применимой юрисдикции.

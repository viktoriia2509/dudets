# JOYSTICK / dudets — версия 3

Это версия сайта с отдельными страницами, корзиной, регистрацией покупателей, личным разделом «Мои заказы» и восстановлением базовых данных Firestore.

## Структура

```text
index.html              — главная страница
collection.html         — отдельная страница коллекции товаров
documents.html          — отдельная страница документов
contacts.html           — отдельная страница контактов
assets/css/styles.css   — дизайн сайта
assets/js/config.js     — настройки Firestore и проекта
assets/js/app.js        — логика сайта, корзины, регистрации, заказов и админки
assets/docs/            — сюда можно класть PDF-документы
assets/images/          — сюда можно класть изображения
```

## Что добавлено в версии 3

1. У зарегистрированного пользователя появляется кнопка **«Мои заказы»**.
2. В «Моих заказах» показываются все заказы, оформленные после входа в этот аккаунт.
3. Добавлена авто-синхронизация с Firestore каждые несколько секунд.
4. Если коллекция `settings` в Firestore пустая, сайт автоматически создаёт недостающие ключи: `products`, `texts`, `contacts`, `design`, `site_docs`, `users`, `orders`, `admin_login`, `admin_pwd`.
5. В админке во вкладке «Настройки» добавлен блок **«Облачная база Firestore»**:
   - восстановить Firestore из данных текущего браузера;
   - заполнить недостающие ключи;
   - сбросить Firestore к базовым данным.

## Как заменить файлы на GitHub

В репозитории нужно заменить старые файлы и папки на содержимое этой папки.

В корне репозитория должно быть так:

```text
index.html
collection.html
documents.html
contacts.html
README.md
SECURITY.md
assets/
database/
```

Не загружайте ZIP-файл как сайт. ZIP нужно распаковать, а на GitHub загрузить его содержимое.

## Как работают «Мои заказы»

Заказ привязывается к пользователю только если он оформлен после входа в аккаунт. Если пользователь оформил заказ без входа, такой заказ попадёт в админку, но не появится в «Моих заказах».

## База данных

Сайт использует Firebase Firestore. GitHub хранит только файлы сайта. Данные хранятся отдельно в Firestore и дублируются в `localStorage` браузера.

Ключи данных:

```text
products     — товары
texts        — тексты сайта
contacts     — контакты
site_docs    — документы
users        — зарегистрированные пользователи
orders       — заказы из корзины
design       — шрифты и размеры текста
admin_login  — логин админки
admin_pwd    — пароль админки
```

## Если база «отлетела»

1. Открой сайт в том браузере, где раньше редактировались товары/заказы.
2. Войди в админку.
3. Перейди в **Настройки → Облачная база Firestore**.
4. Нажми **«Восстановить Firestore из этого браузера»**.

Это сработает только если данные ещё есть в `localStorage` этого браузера. Если Firestore очищен и в браузере тоже нет старых данных, старые заказы и пользователи восстановить нельзя без заранее созданного backup/export.

## Важно по безопасности

Регистрация и вход покупателей сейчас реализованы на фронтенде. Это удобно для проверки логики, но не является полноценной защищённой авторизацией. Для реального магазина с персональными данными и заказами нужно подключать Firebase Auth или серверную авторизацию и закрывать Firestore Rules.
